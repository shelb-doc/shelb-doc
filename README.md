## 👾 About Me

Hey! I'm **Shelby**, a Senior Software Development Engineer in Test based in Atlanta, Georgia.

I started my journey in art and web design before finding my way into software quality engineering.

Turns out, having an eye for detail and questioning absolutely everything translates pretty well into QA.

These days, I work across UI automation, API and integration testing, test framework development, CI/CD, and software reliability.

I enjoy figuring out **why something broke**, how to reproduce it, and what we can do to prevent it from happening again.

My approach is pretty simple:

- 🧪 **Test with purpose.** Automation should verify meaningful behavior.
- 🔍 **Question assumptions.** "It works on my machine" is a starting point, not proof.
- 🛠️ **Build for maintainability.** Tests should help engineers, not become another problem.
- 🤝 **Quality is a team sport.** Developers and QA work better together.
- 🚀 **Keep learning.** There's always another framework, tool, or weird bug to investigate.

I build things. I break things. Then I figure out why they broke.

## 🔬 What I'm Working On

My focus goes beyond getting tests to pass.

I'm interested in building reliable automation that helps teams understand what they're shipping and why they can trust it.

**Current areas of focus:**

- 🎭 **Playwright migration:** Moving UI scenarios from Selenium-based infrastructure into maintainable Playwright automation.
- 💎 **Ruby/Cucumber:** Developing and maintaining API and integration testing workflows.
- ⚙️ **CI/CD reliability:** Improving automated execution, reporting, and failure investigation.
- ☁️ **AWS:** Expanding my knowledge of cloud infrastructure, Lambda testing, and serverless workflows.
- 📋 **Spec-Driven Development:** Exploring how requirements, tests, and implementation can stay aligned.
- 🤖 **AI-assisted engineering:** Learning how AI tools can support test design, code reviews, debugging, and development workflows.

I'm particularly interested in the intersection of **test automation, developer experience, and engineering reliability**.

## 🧠 Engineering Principles

A few things experience has taught me:

**A passing test doesn't always mean the feature works.**

**Flaky tests are a problem worth investigating, not just rerunning.**

**Good automation needs observability, useful assertions, and maintainable design.**

**AI-generated code still needs human judgment and verification.**

**The best testing strategy starts with understanding risk.**

And perhaps most importantly:

> "But how are we testing it?"
